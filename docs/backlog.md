# 보류 목록

리뷰에서 찾았지만 지금 고치지 않기로 한 위험. 관련 작업을 시작할 때 다시 본다.

| 출처 | 내용 | 다시 볼 시점 |
| --- | --- | --- |
| WO-003 리뷰 2 | `req_id`가 없는 메시지는 `(dir, msg)`별로 `k` 카운터를 공유한다. 같은 이름의 무ID 메시지(하트비트 등)가 생기거나 사라지면 뒤 메시지의 `k`가 밀려 계획이 엇나간다. | 연결 단위 메시지(하트비트, 핸드셰이크)를 프로토콜에 넣을 때 |
| WO-007 리뷰 1 | 재현 파일의 `harness.git`은 커밋 안 된 변경이 있어도 HEAD만 기록하고, 재생할 때 하네스 버전·계약 파일·링크 프로필을 비교하지 않아 환경이 다르면 "다이제스트 다름"만 나온다. 작업 트리 변경 여부, 계약 파일 해시, 프로필을 저장해 재생 때 비교한다. | 재현 파일을 다른 장비나 사람과 주고받을 때 |
| WO-007 리뷰 2 | editable이 아닌 설치에서는 `runner.ROOT`가 계약 파일을 못 찾는다(계약 YAML이 wheel에 없음). 계약 파일을 패키지 데이터로 옮기거나 경로를 설정으로 받는다. | 패키지로 배포할 때 |
| WO-007 리뷰 5 | 재현 파일에 Python 버전이 없다. 다이제스트가 `random.Random`의 동작에 의존하므로 버전이 바뀌면 재생이 실패할 수 있다. 버전을 기록하고 다르면 경고한다. | 리뷰 1과 함께 |
| WO-008 리뷰 1 | `shrink.default_delay_sends`는 "프로필 하한 지연으로 처리된 송신"이라 설명되지만, `base: random` 계획에서는 그 송신들이 키 기반 무작위 지연을 받는다. 의미를 문서화하거나 `unplanned_delay_sends`로 이름을 바꾼다. | `base: random` 계획을 축소할 때 |
| WO-008 리뷰 3 | `plan_report`는 중복 장애의 사본이 모두 연결 끊김(`connection_lost`)으로 사라져 효과가 없던 경우를 보고하지 않는다. `faults_lost_to_disconnect`에 포함한다. | 계획기가 중복과 끊김을 함께 쓰기 시작할 때 |
| WO-009 리뷰 5 | 계획기 타임라인은 250줄 뒤를 생략하고 시간을 밀리초로 반올림한다. 후반 위반의 문맥과 마이크로초 단위 시각을 조회할 경로를 제공한다. | 긴 계획이나 경계 시각을 겨냥하는 시행을 설계할 때 |
